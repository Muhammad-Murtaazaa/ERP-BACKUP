# Industry packs and fit-gap coverage
A broad core supports many industries; specialized workflows, accounting, regulation and terminology require packs. Packs depend on verified module capabilities and own their extensions/templates, never bypass financial or security controls.

| Pack | Core modules | Additional required scope before claiming fit |

## Pack structure
Manifest + vocabulary + prerequisite features + custom schemas + configuration defaults + approved COA mappings + document/report templates + workflows + localization applicability + fixtures + synthetic scenario + fit-gap checklist + operating instructions. Extending a pack creates a version, not a customer branch of core.

## Fit-gap method
List client's end-to-end flows and exceptions; map requirement IDs; identify covered/partial/missing/provider-required/regulated features; verify transaction volumes/device/offline needs; record data migration; map local geography and accounting; prototype difficult tasks; agree gaps and acceptance before calling the solution enterprise-ready.

## Specialized limits
No single generic pack guarantees healthcare, banking, public procurement, regulated food/pharma or every local payroll. These are scoped and verified products. Demonstrate a complete process and failure recovery for each advertised industry; do not reuse a generic sales demo as evidence.
